# Развернуть у себя: машины, модели, порядок

Что нужно, чтобы поднять morag-web на своих записях с нуля, и в каком порядке. Механика каждого
шага — в соседних документах (ссылки по ходу); здесь — состав и последовательность.

## Три роли

```
 ┌─ Mac на Apple Silicon ─────────────┐     ┌─ LLM-шлюз (OpenAI-совместимый) ─┐
 │ транскрибация: whisper, pyannote,  │────▶│ текстовая модель с tool calling  │
 │ CAM++, выравнивание; экран из видео│     │ модель Vision (кадры слайдов)    │
 └──────────────┬─────────────────────┘     │ dense-эмбеддер                   │
                │ сайдкар <имя>.json         └──────────────▲──────────────────┘
                ▼                                           │
 ┌─ Linux-сервер с Docker ────────────────────────────────────┴───┐
 │ Qdrant · sparse-эмбеддер GTE · движок ×2 (корпус и одна запись) │
 │ индексатор (разово / по cron) · сайт (uvicorn за обратным прокси)│
 └─────────────────────────────────────────────────────────────────┘
```

Для пробы всё, кроме LLM, помещается на один Mac: Docker Desktop поднимает поисковый стек,
сайт запускается рядом. Разделять имеет смысл, когда сайтом пользуются другие люди: транскрибация
занимает машину часами, а сайт должен отвечать всегда.

## Машины

| роль | минимум | удобно | заметки |
|---|---|---|---|
| **Mac (транскрибация)** | Apple Silicon, 16 ГБ, ~8 ГБ диска | 32 ГБ и больше | whisper — на MLX, диаризация и выравнивание — на MPS; Intel не подойдёт. Один whisper держит 10–12 ГБ, поэтому на 16 ГБ задачи идут строго по одной. Второй whisper для арбитража (см. ниже) — ещё ~3 ГБ весов и памяти |
| **Сервер (поиск и сайт)** | 4 vCPU, 8 ГБ, Linux, Docker | 8 vCPU, 16 ГБ | GPU не нужен. Sparse-эмбеддер — торч на CPU: до 2 ГБ при `indexing.concurrency: 1`, лимит контейнера 5 ГБ. Каждый процесс движка ~0.5 ГБ, Qdrant — по размеру индекса (≈1 ГБ на 15 тыс. чанков с dense 2560). Python 3.10+ для сайта |
| **Хранилище видео** | любой веб-сервер | — | Сайт видео не раздаёт: плеер тянет файл из архива по `media_base`. Архив обязан отвечать `Accept-Ranges: bytes` и `206` на диапазон, иначе не работают перемотка и караоке |

Диск сервера: образы движка ~10 ГБ (amd64), индекс, а если записи загружают через сайт (`docs/upload.md`) —
ещё и видео в архиве и зеркало установщика (~3 ГБ).

## Модели

### Транскрибация (на Mac, скачивает `morag/services/asr-adaptor/deploy/mac/fetch-models.sh`)

| модель | размер | зачем | откуда |
|---|---:|---|---|
| `whisper-podlodka-turbo` (MLX) | 1.5 ГБ | распознавание, оба прохода | MLX-конверсия `bond005/whisper-podlodka-turbo` на HF (адрес — в `fetch-models.sh`), свободно |
| pyannote `speaker-diarization-3.1` + `segmentation-3.0` | ~6 МБ | кто когда говорит | HF, **gated**: токен с ролью read и принятые условия на обеих страницах |
| pyannote `wespeaker-voxceleb-resnet34-LM` | 26 МБ | голоса для диаризации | HF, свободно |
| CAM++ (`3dspeaker_speech_campplus_sv_zh_en_16k-common_advanced.onnx`) | 27 МБ | отпечатки голосов, реестр `Speaker_N` | релизы `k2-fsa/sherpa-onnx` на GitHub |
| MMS_FA (torchaudio) | 1.3 ГБ | пословное выравнивание (караоке) | приезжает сам при первом выравнивании |
| *по желанию:* второй русский whisper в MLX, например `whisper-large-v3-russian` | ~3 ГБ | второе мнение при арбитраже (`ASR_SECOND_MODEL`) | MLX-сборку положить в `~/asr-stack/models/<имя>/` — бэкенд находит модели по каталогу. Ценна тем, что ошибается в ДРУГИХ местах, чем основная; модель той же школы почти бесполезна |

### Поиск и ответы (на сервере)

| что | где | заметки |
|---|---|---|
| **sparse** `Alibaba-NLP/gte-multilingual-base` | контейнер `embedder-gte`, веса скачиваются при сборке образа | сборка требует доступа к huggingface.co |
| **dense-эмбеддер** | LLM-шлюз, `/embeddings` | проверено на `Qwen/Qwen3-Embedding-4B` (dim 2560). ⚠️ Выбрать ДО первой индексации: отпечаток индекса — `sha256(model\|dim\|base_url)`, смена любой части — переиндексация (`docs/deploy.md`) |
| Qdrant | образ `qdrant/qdrant:v1.17.0` | — |

### LLM (через шлюз, OpenAI-совместимый `chat/completions`)

| модель | кто зовёт | требования |
|---|---|---|
| **текстовая** | агент движка, стадии транскрибации (глоссарий, правки, читатель), справки чанков при индексации, классификатор, аннотации, вопрос к записи | **штатные `tool_calls`** — модель, которая печатает `<tool_call>` текстом, агентский цикл не тянет; окно от 120k токенов (вопрос к одной записи кладёт её целиком: медиана 20k, хвост до 150k); думание выключаемо. Проверено на MoE класса 30B-A3B |
| **Vision** | `describe_slides.py`, `screen_refs.py` (экран из видео) | думание выключать явно, иначе ответ съедается рассуждением. Проверено на 9B. Без экрана из видео не нужна |

Шлюз может быть облачным (OpenRouter и т. п.) или своим (vLLM, Open WebUI). Адрес пишется
**без `/v1`**, если у шлюза путь `/api/chat/completions` — SDK дописывает только хвост.

## Порядок

1. **Чекауты рядом:** `morag` (движок) и `morag-web` (сайт), корпус — отдельный каталог или
   репозиторий по шаблону `corpora/example/` (`docs/corpus-layout.md`).
2. **LLM-шлюз:** адрес, ключ, имена двух моделей и эмбеддера. Проверить `tool_calls` одним
   запросом с инструментом до всего остального.
3. **Стек транскрибации на Mac** — `morag/services/asr-adaptor/deploy/mac/README.md`:
   `install.sh` → вписать ключ LLM и `HF_TOKEN` в `~/.asr-stack.env` → `install.sh` →
   `fetch-models.sh` → `stack.sh up`. ⚠️ До первой записи настроить голоса в профиле корпуса
   (`asr-profile.env`): дефолты рассчитаны на подкаст и на докладе с вопросами из зала сводят
   всех в одного человека.
4. **Записи:** `corpora/example/transcribe.sh` → сайдкар → `tools/make_record.py` →
   `records/<ветка>/<второй уровень>/<id>/` (`docs/record-format.md`). По желанию — экран из
   видео (`docs/screen-layer.md`, `pip install -r tools/requirements-video.txt`).
5. **Образы движка** (из чекаута morag; для сервера без доступа к ghcr.io и huggingface.co —
   собрать там, где доступ есть, с `--platform linux/amd64`, и перевезти `docker save`):
   ```bash
   cd morag
   docker build -f services/pipeline/Dockerfile -t morag-pipelines:latest .
   docker build -t morag-embedder-gte:latest services/embedder_gte
   docker build -t morag-morag-indexer:latest .
   ```
6. **Поисковый стек и индексация** — `deploy/docker-compose.yml`, `docs/deploy.md`.
   ⚠️ Прочитать раздел «Индексация — опасная операция» ДО первого запуска: индексатор
   синхронизирует источник целиком и удаляет всё, чего в нём нет.
7. **Сайт:** `pip install -r app/requirements.txt`, `app/config.yml` по образцу
   `app/config.example.yml` (корпус, адреса движков, `media_base`, вход — `docs/auth.md`),
   `MORAG_WEB_CONFIG=… python3 -m uvicorn app.main:app`. На сервере — systemd и обратный
   прокси по шаблонам `deploy/server/`.
8. **Загрузка записей коллегами** (по желанию) — `docs/upload.md`: Mac коллеги транскрибирует,
   сервер принимает пакет, собирает запись и индексирует ночью.

## Сеть

- Сервер ходит к LLM-шлюзу (агент, справки чанков, dense-эмбеддер) и к хранилищу видео не
  обязательно — видео тянет браузер. Контейнерам движка прокси гасится явно (`NO_PROXY_EXTRA`
  в compose): к внутреннему шлюзу через внешний прокси не ходят.
- Mac транскрибации ходит к шлюзу (стадии с LLM) и при установке — к huggingface.co и GitHub.
- Браузер посетителя ходит к сайту и к хранилищу видео.
