# Личные записи: загрузить себе, дать ссылку, показать всем

Человек загружает свою запись и решает, кому она видна: **только ему** (и тем, кому он дал
ссылку) или **всем**. Решение можно поменять со страницы записи в любую сторону. Включается
`privacy.enabled` в `app/config.yml` и требует входа (`auth.enabled`): без входа у записи нет
хозяина.

## Модель

**Видимость — это каталог, а не флаг.** Личная запись лежит в
`<пространство>/records-private/<логин>/<ветка>/<уровни>/<id>/`, общая — в
`<пространство>/records/<ветка>/<уровни>/<id>/`. Под логином раскладка та же, что дают правила
`hub.yml::routing`, поэтому «показать всем» — это перенос каталога, а ветка, год и шапка
записи не меняются.

Почему каталог: индексатор движка смотрит только на `sources[].path` (= `records/`). Личная
запись в поисковую базу не попадает **по построению** — промах в признаке или фильтре не может
её туда унести. Тот же приём, что у второго корня пространства (`content.records` списком).

**Кто ещё видит** — `record.meta.json` → `access`:

```json
"access": {"owner": "login", "link": "<соль ключа ссылки>",
           "granted": [{"login": "…", "name": "…", "at": "ГГГГ-ММ-ДД"}]}
```

Не в шапке: шапка уезжает в payload каждого чанка, и смена доступа стоила бы переиндексации.
У общей записи блок тоже бывает — с одним `owner`: так автор может скрыть её позже.

**Видео личной записи** лежит в `upload.private_media` (по умолчанию `<семья>/private-media`)
тем же относительным путём, что в шапке (`Uploads/<id>.mp4`). Отдаёт его сайт
(`/api/records/<id>/media`, с диапазонами для перемотки) после проверки доступа. Открытый
архив (`media_base`) его не раздаёт: архив обычно без входа, а id записи угадывается по дате и
названию. «Показать всем» переносит файл в архив — путь в шапке прежний.

## Кто что видит (политика `owner_link`)

| | общая | личная, хозяин | личная, открыл по ссылке | личная, админ | личная, остальные |
|---|---|---|---|---|---|
| в списке | да | да («мои записи», замок) | да | **нет** | нет |
| страница, слова, кадры, видео | да | да | да | да (по адресу) | **404** |
| вопрос к записи | да | да (прямой путь) | да | да | 404 |
| ссылка, кто открыл, «показать всем» | — | да | нет | да | — |

- Чужому — **404, а не 403**: «нельзя» сообщает, что запись есть. Кривой ключ ссылки — тот же 404.
- Админ открывает чужую личную по адресу (поддержка), но его лента и ответы не смешиваются с
  чужим личным.
- Ссылка открывает запись **только вошедшим**; открывший получает доступ насовсем (запись
  появляется в его списке), пока хозяин не уберёт его из «Открывали». «Новая ссылка» убивает
  старые ссылки, но открывших не выгоняет.
- Политика — подключаемый объект (`privacy.policy`, `app/content/access.py::POLICIES`), как
  провайдеры входа. Команды и отделы, чёрный список, журнал доступа подключаются в ту же точку.

## Двери, через которые запись могла бы утечь (все закрыты)

Одна точка решения — `app/content/access.py` (политика) и `app/api/access.py` (заслонки):

- список `/api/records` — `visible_records`; счётчики витрины и `/api/health` — только общие;
- всё про одну запись (`words`, `transcript.md`, `slides.pdf`, `files`, `frame`, `frames`) —
  через `_meta` → `visible_or_404`;
- вопрос к записи (`/api/ask` с `context.record_id`) — 404 чужому; личной — только прямой путь
  (запись целиком в окне модели): в индексе движка её нет, и вопрос туда не уходит;
- правки (`edits`, `fields`, материалы) — каталог ищется с той же проверкой;
- снимок голосов (`/api/voices*`) — без записей, `intros` и кандидатов из невидимых личных;
- поиск написаний (`/api/tokens`) смотрит только на общие корни; метки для окна загрузки и
  выжимка корпуса для авто-темы — только общие;
- цитаты движка (`by_path`) личных не разрешают: в индексе их нет.

Инструменты корпуса личные корни по умолчанию **не видят** (`spaces.records_dirs(private=False)`):
генераторы отчётов и разметки пишут свои файлы в git корпуса. Видят их те, кому нужно по делу:
поиск записи по id, полная пересборка (`make_record --all`), снимок голосов.

## Загрузка

Окно приложения: галочка «Показать всем» (по умолчанию снята — умолчание сайта
`privacy.upload_default`). Командная строка: `--public` / `--private`. Старое окно без поля —
решает умолчание сайта. Сервер берёт хозяина из сессии, а не из манифеста; личная запись
собирается `make_record --owner <логин>` прямо в личный корень и в индексацию не ставится.

Старым загрузкам автора проставляет `tools/access_backfill.py` (из «Имя (логин)» в
`sources.upload.by`; без `--write` — отчёт). Видимость он не трогает.

## Страница записи

Тот же замок, что на карточке (`web/js/records/lock.js` — один компонент на оба места), в правом
верхнем углу шапки: закрытый у личной, бледный открытый у своей общей. Меню полнее карточного:
«Скопировать ссылку», «Новая ссылка», «Показать всем» и «Открывали по ссылке» с ✕; у общей —
«Сделать личной». Опасное — вторым щелчком, без диалогов браузера. Ссылка вида
`/<слаг>/rec/<id>?k=<ключ>`: читалка сначала закрепляет доступ, потом ищет запись в списке, ключ
из адреса убирает.

## Список записей

У личной записи — закрытый замок в правом верхнем углу карточки, цветом рамки; при наведении он
ярчеет, подсказка появляется сразу (своя, не `title`: браузерная ждёт секунду). У своей общей —
открытый замок, только при наведении на карточку. Щелчок по замку у автора и админа — меню прямо
на карточке: у личной «Скопировать ссылку» и «Показать всем», у общей «Сделать личной»
(подтверждение вторым щелчком). У открывшего по ссылке щелчок по замку открывает запись.

## Окно загрузки после приёма

Личная запись: окно говорит «видна только вам» и даёт адрес С КЛЮЧОМ ссылки («Скопировать
ссылку»). ⚠️ Ключ не хранится в статусе загрузки: статус (`/api/upload/<id>`) читает любой с
правом загрузки, а id угадывается. Ручка статуса считает ключ на лету и отдаёт его только автору и
админу; остальным у личной записи не отдаёт ни адреса, ни id.

## Грабли и решения

- **Общая → личная:** запись выпадает из индекса движка при ближайшей индексации (индексатор
  удаляет документы, которых нет в источнике). Чтобы не ждать, переключение сразу запускает
  `privacy.reindex` (пусто — `upload.index`) в фоне. Пока прогон идёт (минуты), чанки ещё в
  базе; не задано ни то ни другое — запись уйдёт из поиска при плановом прогоне.
- **Запись без автора** (перенесённая из старого источника) скрыть нельзя — 409: личная
  принадлежит кому-то одному, и решать это вслепую нельзя.
- **Флаг выключен** — уже лежащие личные записи по-прежнему скрыты от чужих (безопасная
  сторона); выключены только приём «себе», ссылка и переключатель.
- Имя личного корня одно на сайт и инструменты (`records-private`); тест сверяет константы.

## Дальше: доступ на уровне ретрива

Сейчас личная запись не участвует в общем поиске даже у хозяина — вопросы к ней задаются на её
странице. Следующий шаг — фильтр доступа в движке: личные записи в индексе, а на ретриве агенту
не уходят чанки, недоступные спрашивающему. Каналов, через которые документ доходит до агента,
семь: `search`, `get_doc`, `catalog`, `find_section`, автозагрузка документа по id в вопросе,
перечень значений фильтров и Карта знаний. Фильтр нужен в каждом; источник правды — тот же блок
`access`.
